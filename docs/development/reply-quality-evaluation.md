# 返信品質の意味評価仕様

## 目的

既存の70ケース評価は凍結した回帰ゲートとして維持し、意味の合う自然な言い換えや、本人がそのまま送れるかを別に測る。追加評価の結果を生成処理・候補順位・repairへ直接戻さない。評価器の変更だけで製品品質が上がったように見せない。

評価対象は次の3群に分ける。

1. 一般返信の回帰。正規70ケースと既存の6指標を使い、既存thresholdを維持する。
2. Gold利用の評価。同一相手・別相手・GlobalのGold、検索候補、few-shotなしを分け、検索とstyle adaptationを測る。
3. 送信可能性。相手の直近発言と必要な会話履歴に対し、候補がユーザー本人からそのまま送れそうかを評価する。

## 人手レビュー用ルーブリック

各返信を、出力元・モデル名・既存スコアを伏せて評価する。返信を単独で採点せず、相手の発言と評価に必要な直近履歴も提示する。

| 項目 | 評価の問い | 1 | 3 | 5 |
|---|---|---|---|---|
| 文脈への適合 | 相手の質問・報告に対して、話題と意図の合う返事か | 返事になっていない | 一部合うが不足・ずれがある | 内容に正確に応じている |
| 必要情報 | 必要な回答や反応を含み、余計な質問・説明を足していないか | 重要な回答がない／大きく脱線 | 少し不足または余分 | 必要十分で自然 |
| 事実の根拠 | 本人の好み・経験・予定や相手の行動を勝手に足していないか | 重大な捏造がある | 根拠不明な含みがある | 確認済みの情報だけを使う |
| 会話の自然さ | 距離感・温度・文量・会話の終え方が状況に合うか | 送信に耐えない | 直せば使える | そのまま自然に送れる |
| 送信可能性 | ユーザー本人がほぼ修正せず送るか | 送らない | 大きく直して送る | そのまま送る |

Echoは単語の一致だけで不合格にしない。相手の話題を使っていても、質問への回答・共感・自然な反応として意味がある場合はechoと分類しない。別に「単純な繰り返し」「単純な言い換え」「自然な話題再利用」「文脈を外した新話題」のタグを付け、判定理由を短く記録する。

1と5のどちらかを付けた場合は短い理由を必須とする。評価者は候補を相互に相談せず独立に採点する。LLM評価を追加した場合も、同じ盲検対象を人手が採点するまで閾値・本番ゲートにしない。

## 事前に定める合格条件

- 70ケースの旧thresholdとケース集合を変更せず、既存回帰が通る。
- 意味評価セットは、明示的な直接質問、感情共有、会話終了、話題語の自然な再利用、表記ゆれ・同義表現、事実根拠がないケースを含める。
- Goldありの検索評価ではqueryごとに有用なpair IDを人手で確定し、Recall@k・MRR/nDCG、Negative混入、no-hit時の不要な例文返却を測る。データを会話または相手単位で分割し、同一ペアの学習・評価漏洩を防ぐ。
- 候補の送信可能性は、平均点だけでなく「そのまま送信」「軽微修正」「大幅修正」「不採用」の割合と失敗理由を報告する。
- 2名以上の独立評価がそろうまで、LLM graderとの一致度を主張しない。ordinal weighted kappa、項目別一致率、LLMと人の不一致例を併記する。評価者間の意見が大きく割れた例は協議して基準例へ加える。
- 実APIのモデル差は除外理由にしない。同じ入力・同じ受け入れ基準で3.1と3.5を記録し、モデル・アカウント・repair経路をartifactに残す。

## Trace artifact

各ケースで入力・意図・必要な会話履歴、検索されたpair IDとscore、実際に送信したpromptのhash、生成候補、既存評価、モデルとrepair回数を結び付ける。プロンプト本文の保存は個人情報を含み得るため、ローカル評価で明示的に有効にした場合だけ行う。既定artifactに返信候補や秘密値を含めない。

盲検採点CSVは次のように作り、2名がそれぞれコピーしたCSVへ評価を入力する。入力は既定でモデル名・既存スコアを含まず、順序だけをseedで変える。会話本文を含むため、artifactとCSVはローカルに保管し、共有リポジトリへ追加しない。

```powershell
python scripts/reply_quality_annotations.py export artifact.json ratings-a.csv --seed 14
python scripts/reply_quality_annotations.py export artifact.json ratings-b.csv --seed 87
python scripts/reply_quality_annotations.py agreement ratings-a.csv ratings-b.csv
```

合意計算は5つの1〜5段階評価について完全一致率とquadratic weighted Cohen kappaを出す。Echo分類は4タグの完全一致率を出す。採点データが集まるまでは、LLM graderとの一致度や人間との合意は未測定として扱う。

## 実施状況

既存70ケースの軸が`naturalness`の決定論的代理指標であること、意味の偽陰性と単純な話題再利用の偽陽性があることをコードと既存資料から確認した。既存thresholdは未変更。合成6ケースによるlexical retrieval baselineはRecall@4 1.0、MRR 1.0、Negative混入0件だったが、no-hitケースに無関係なpairを返したため、内容一致のない候補を外す最小ゲートを追加した。これらは小さな合成セットの結果であり、実利用の品質証明ではない。

未実施の項目は、二重盲検の人手評価、LLM graderとの一致度測定、ユーザーGoldによるleave-one-contact-out検索比較、ローカルEmbedding対hybridの測定、実API返信候補の送信可能性評価である。
