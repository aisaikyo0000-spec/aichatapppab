# タップルの会話・デート提案に関する調査メモ

調査日: 2026-10-09

この資料は、マッチングアプリ内の会話から初回デートの提案までを支援する機能の判断材料を整理する。タップルは、利用者が相手の返信をアプリへ貼り付け、候補を自分で実際のアプリへ貼り付けて送る。アプリはタップルと直接連携せず、送信も代行しない。

## 判断の要約

- 返信生成と戦略判断は分ける。返信は直近の相手発言と会話全体に自然に応じ、戦略は「話題を広げる」「反応を待つ」「低圧に誘う」「誘わず終了する」を必要なときだけ提示する。
- 誘う時期をメッセージ数や経過日数だけで決めない。相手自身が示した具体的な関心、会話の相互性、直近の温度、明示された迷い・拒否を根拠にする。返信速度や短い相づちは単独では誘う根拠にならない。
- 趣味の一致は自然な話題や提案の入口に使えるが、会う同意とは扱わない。誘いは一度の明確で断りやすい提案に留め、ためらい・拒否があれば追いかけない。
- 相手の信頼性や現実の安全性を文章だけで判定できるように見せない。利用者が不安を感じる場合は誘わない選択を保ち、公共の場所・個人情報の保護など公式の安全策を優先する。
- 調査対象の多くは観察・自己申告・プラットフォーム独自調査である。成功率を保証する「必勝テンプレート」や最適な誘いのメッセージ数を導く根拠は確認できていない。

## 実装・評価への反映

1. 会話上の現在の意思を優先しつつ、過去の未解消の拒否・安全懸念は後の趣味の話題だけでは消さない。明確な解消表明だけを解除根拠にする。
2. 招待可能性は相手本人の具体的な活動関心と会話の相互性で評価する。単語一致、一般的な好意、返信速度、短い相づちだけでは誘わない。
3. 戦略評価には、温かい相互会話、反応の薄い会話、相手の迷い・拒否、引用された第三者の意見、安全に関する不安、自然な終了を含める。正規表現の合否だけで文章品質を判定しない。
4. 返信文は本人がそのまま送れる自然さを別に人が確認する。戦略ベンチやマーカーを通過したことをデート成立の証明として報告しない。
5. 実運用では、誘いの有無・文面・相手の返答・断りやすさを個人情報を減らした形で記録し、本人の採用・修正・拒否を評価の主軸にする。本人の明示的な許可なしに会話履歴を外部サービスへ送らない。

## 未解決

- 今回はタップル利用者の生の会話ログを入手・分析していない。個人の成功談やX投稿は、宣伝・選択バイアス・再現性の問題が大きいため、実装ルールの決め手に使わない。
- 具体的に何往復後に誘うべきか、何日待つべきかという閾値を裏付ける、タップル固有の比較試験は確認できていない。
- Gemini実生成のTappleケースは、API利用制限が解除されてユーザーが再開を確認した後に実施する。現時点のコードテストは戦略ロジックの回帰であって、実出力品質の評価ではない。
